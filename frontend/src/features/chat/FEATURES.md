## chat

- **What it does:** Renders the user-facing chat interface — a globally-mounted floating widget (launcher → teaser → panel; PLAN 4.7.4) — and proxies chat requests to the Python automation API, streaming answers and citations back to the browser; also proxies thumbs up/down feedback. The old standalone full-page `/chat` route was removed in PLAN 4.7.7 at the user's explicit request ("the open chat needs to be fully replaced with the widget") — the widget is now the only chat surface.
- **Path / owning app:** `frontend/src/features/chat` — owned by `frontend`.
- **Language / framework / runtime:** TypeScript, Next.js 15 (App Router) + React 19, Node.js LTS (server) and the browser (client components).
- **Deployment unit:** Ships inside the `web` Next.js application deployment.
- **Exported symbols (`index.ts`):** `ChatWidget` (the floating launcher/teaser/panel root, PLAN 4.7.4 — mounted once, globally, by `app/layout.tsx`); `ChatSessionProvider` (the shared conversation context, also mounted once by `app/layout.tsx`, PLAN 4.7.4 architecture decision D0 — as of PLAN 4.7.7 also carries the widget's UI-copy `locale`); the view-model types `ChatMessage`, `MessageRole`, `MessageStatus`; and the server route handlers `handlePostChat`, `handlePatchFeedback` (composed by `app/api/chat/**/route.ts`). Internals (`ui/`, `api/`, `model/`, `server/`) are private behind this root. `ChatPanel` and its backing "page" variant were removed in PLAN 4.7.7 along with the `/chat` route.
- **Internal structure:** `ui/` (`chat-session-provider` — conversation state machine behind `ChatSessionProvider`/`useChatSession`, mounted once at the app root; also owns `locale`/`setLocale` as of PLAN 4.7.7; ## embed

- **What it does:** Owns the Obi embed surface — the host-side loader script (`obi.js`), the `/embed` iframe frame's CSP, and the `postMessage` bridge between a platform's host page and the widget frame. A platform adds one `<script>` tag; the loader mounts the iframe, performs the fixed three-message host→frame handshake (`obi:open` / `obi:token` / `obi:clear`, `OBI_MESSAGE_TYPES`), and hands the widget the platform-signed JWT. The verified token is the scope authority backend-side; everything this feature carries is transport, never trust.
- **Path / owning app:** `frontend/src/features/embed` — owned by `frontend`.
- **Language / framework / runtime:** TypeScript. `loader.ts` is a standalone esbuild IIFE (`build:obi`) running in the HOST page's realm; `iframe-bridge.ts`/`csp.ts` run in the browser; `platforms.ts` is server-only (`node:fs`).
- **Deployment unit:** Ships inside the `web` Next.js application deployment; `loader.ts` is additionally bundled to `public/obi.js`.
- **Exported symbols (`index.ts`, the CLIENT-safe root):** `initIframeBridge`, `getToken` (from `iframe-bridge`); `isLocalOrDevEnv` (from `csp`, re-exported at **substep 8.4.1** so the chat standalone-preset selector reads the local/dev signal through this root instead of deep-importing `./csp`); the type `InitIframeBridgeOptions`; and the postMessage contract types `ObiMessage`/`ObiMessageType`/`ObiOpenMessage`/`ObiTokenMessage`/`ObiClearMessage` + `OBI_MESSAGE_TYPES` (re-exported from `@omniboost/contracts`). Deliberately does NOT re-export `platforms.ts` — a barrel mixing browser-safe code with `node:fs` breaks the client webpack bundle (confirmed `UnhandledSchemeError: node:fs`); server-only consumers import `./platforms` directly, which carries `import "server-only"`.
- **Internal structure:** `loader.ts` — the host-page script: mounts the iframe, runs the three-message handshake, and recovers the panel after an iframe reload (re-posts `obi:open` + re-sends the token). `iframe-bridge.ts` — the frame-side receiver: validates message origin/shape, holds `currentToken` in memory, exposes `getToken()`, and fires `onScopeChange` when a token renewal crosses into a different corpus/identity. As of **substep 8.4.2** (panel mi-contract), `decodeScope` reads the extended `context.slots` claim in addition to the legacy `integration`/`company_id`: a display-only, order-independent `slotsSignature` (fixed `pos;pms;accounting` key order, `null` for a legacy single-integration note) joins the `sameScope` comparison, so a renewal that changes only a SLOT (same company, same integration) now correctly resets the conversation — the pre-8.4.2 bridge read only `integration`/`company_id` and missed that. This is the **T6** contract row: the note still rides `obi:token` as an opaque signed JWT string, so the richer claims change NO message type (a T6 no-op for the message contract — an old host sending the legacy payload is byte-compatible). The slot signature is never trust-bearing (the backend `TokenVerifier` is the authority) and lives in memory alongside `currentToken` — never persisted or logged. `csp.ts` — pure, edge-safe env/CSP helpers (`isLocalOrDevEnv`, no `node:fs`). `platforms.ts` — server-only read of `knowledge-base/config/platforms.json` for the `/embed` frame's `frame-ancestors` CSP.
- **Allowed importers:** `frontend/src/app` (the `/embed` frame page, `middleware.ts`) and `frontend/src/features/chat` (for `getToken()` and `isLocalOrDevEnv`) — only via the public root `@/features/embed`, except the server-only `./platforms` imported directly by server consumers.
- **Contracts consumed:** `@omniboost/contracts` — the `ObiMessage` postMessage union + `OBI_MESSAGE_TYPES`. The token itself is an opaque JWT string on the wire; the embed frame never decodes it for trust (the backend verifier mirrors `packages/contracts/src/token-claims.json`, which gained the structured `context.slots` form at **substep 8.1.2** alongside the never-dropped legacy single-`integration` form).
- **External systems called:** None directly — it relays the host↔frame handshake and the token; the chat feature's proxy is what reaches the backend.
- **Database tables owned:** None.
- **Where it validates untrusted input:** `iframe-bridge.ts` — every inbound `postMessage` is origin-checked against `allowedOrigins` and shape-checked (`isObiMessage`) before it is honoured; a rejection is logged as a fixed code string, never the token value.
- **Tests location / risky paths:** `frontend/src/features/embed/tests` — `iframe-bridge.test.ts` (origin/shape rejection, token-in-memory-only, scope-change detection; **substep 8.4.2** added: a slot-shaped `context.slots` note accepted and threaded exactly like a legacy note (T6 opaque-JWT no-op), a slot-only renewal resetting the conversation, an identical-slots renewal NOT resetting, a legacy→slot cross resetting, and a memory-only assertion that the slot values never reach sessionStorage/localStorage/a cookie/a log — BIT-9's "token value never reaches any console output" still holds), `loader.test.ts` (the host-page handshake + reload recovery; note: a pre-existing jsdom async-teardown race logs an unhandled `postMessage` rejection after the suite's tests pass — unrelated to this feature's behavior, in the unchanged `loader.ts`), `frame-csp.test.ts` (the `/embed` CSP). The three-message `ObiMessage` contract is host→frame only, so a 401 renewal round-trip has no channel yet (see chat's `onUnauthorized`).
- **Run / test commands:** Build the loader: `pnpm --filter web build:obi`. Test: `pnpm --filter web test` (vitest).
