This file documents every feature in apps/web/src/features. Each block below maps to one folder in that directory. A feature without a block here is undocumented and incomplete.

## chat

- **What it does:** Renders the user-facing chat interface — a globally-mounted floating widget (launcher → teaser → panel; PLAN 4.7.4) — and proxies chat requests to the Python automation API, streaming answers and citations back to the browser; also proxies thumbs up/down feedback. The old standalone full-page `/chat` route was removed in PLAN 4.7.7 at the user's explicit request ("the open chat needs to be fully replaced with the widget") — the widget is now the only chat surface.
- **Path / owning app:** `apps/web/src/features/chat` — owned by `apps/web`.
- **Language / framework / runtime:** TypeScript, Next.js 15 (App Router) + React 19, Node.js LTS (server) and the browser (client components).
- **Deployment unit:** Ships inside the `web` Next.js application deployment.
- **Exported symbols (`index.ts`):** `ChatWidget` (the floating launcher/teaser/panel root, PLAN 4.7.4 — mounted once, globally, by `app/layout.tsx`); `ChatSessionProvider` (the shared conversation context, also mounted once by `app/layout.tsx`, PLAN 4.7.4 architecture decision D0 — as of PLAN 4.7.7 also carries the widget's UI-copy `locale`); the view-model types `ChatMessage`, `MessageRole`, `MessageStatus`; and the server route handlers `handlePostChat`, `handlePatchFeedback` (composed by `app/api/chat/**/route.ts`). Internals (`ui/`, `api/`, `model/`, `server/`) are private behind this root. `ChatPanel` and its backing "page" variant were removed in PLAN 4.7.7 along with the `/chat` route.
- **Internal structure:** `ui/` (`chat-session-provider` — conversation state machine behind `ChatSessionProvider`/`useChatSession`, mounted once at the app root; also owns `locale`/`setLocale` as of PLAN 4.7.7; as of PLAN 7.5, `sendMessage` accepts an optional `SentImage[]` second arg, attaches the wire `ImageAttachment[]` to the newest history turn only (ADR-0009 decision 2), stores render-only preview images on the user `ChatMessage`, and reads `imageAnalysis` back off the `done` event onto the assistant `ChatMessage`; `chat-widget` — PLAN 4.7.4's floating-widget root: renders `ChatLauncher` + (conditionally) `TeaserPopup` while closed, or `FloatingFrame` wrapping `panel-body` while open, driven by `use-widget-visibility`; `use-widget-visibility` — the launcher/teaser timing state machine (3000ms initial teaser, 20000ms repeat, matching the mockup's own `scheduleTeaser` exactly); `chat-launcher` — the closed-state circular button, pulses via `launcher-pulse` while the teaser is visible, locale-aware title (PLAN 4.7.7); `teaser-popup` — the proactive nudge card, `teaser-in` entrance keyframe, locale-aware copy (PLAN 4.7.7); `floating-frame` — the widget's open-state chrome: a fixed-position overlay pinned to the right edge, tagged `data-obi-widget-root` so the screenshot capture can hide it during capture (PLAN 4.7.7); `panel-body` — composition root for the widget, composing `panel-header` + `contour-background` + `message-list` + `composer` (PLAN 4.7.3, no longer takes a `variant` prop as of 4.7.7), also owns the screenshot-capture handler and the flash overlay; `panel-header` — the chrome bar (assistant mark/name, "···"/screenshot/language/close icon row — screenshot button added PLAN 4.7.7), owns the three menus'/handlers' mutually-exclusive-where-applicable state, locale-aware labels, wires "Restart conversation" to `useChatSession().restart()`; `menu`/`menu-item` — shared dropdown shell for both header menus; `language-menu` — the six-locale switcher, made real in PLAN 4.7.7 (switches `ChatSessionProvider`'s `locale`, no longer a stub); `contour-background` — the ambient wavy-line SVG behind the message thread (PLAN 4.7.7, pixel-exact to the mockup); `message-list` — locale-aware greeting/suggestion-chip as of 4.7.7 (the chip's copy is adapted, not the mockup's literal Stripe-demo text — see PLAN.md 4.7.7); `message-bubble` — as of PLAN 7.5, renders a user turn's attached images as thumbnails (click-to-zoom via `ImageLightbox`) and, for an assistant turn, a separate labeled `ImageAnalysisSection` for `imageAnalysis` (isolated in its own subcomponent, same pattern as `Greeting`/`SuggestionChip`, so `useChatSession` is only required when a turn actually has one — existing no-provider tests stay unaffected); `typing-indicator`; `composer` — a `forwardRef` exposing `ComposerHandle.addAttachmentFile` so the header's screenshot button can inject a real captured image into the same attachment pipeline as file-picker/paste (PLAN 4.7.7); as of PLAN 7.5, `send()` base64-encodes staged attachments and hands them to `onSend(text, images)` instead of dropping them, and a persistent `imageDisclosure` copy (the C6 gap: image bytes are not PII-redacted) shows while an image is staged; `attachment-strip` — pre-send thumbnail preview strip (`docs/rag/OBI-WIDGET-DESIGN.md` §6; file-picker + clipboard-paste + screenshot); `image-lightbox` — full-size click-to-zoom preview (PLAN 4.7.8), rendered by both `attachment-strip` (pre-send) and `message-bubble` (post-send, PLAN 7.5); `icon-button`, `assistant-mark` — feature-only components), `api/` (`chat-client` — browser SSE client over `/api/chat`), `model/` (`messages` — render view-model, plus `MessageImage`/`SentImage` (PLAN 7.5); `i18n` — the widget's own six-locale UI copy table, PLAN 4.7.7, plus `imageDisclosure`/`imageAnalysisLabel` (PLAN 7.5)), `server/` (`route-handlers` — the Next.js proxy to `apps/automation`; `validation` — inbound shape checks, C3).
- **Allowed importers:** `apps/web/src/app` (routes/pages/layout) only, and only via the public root `@/features/chat`. No other feature or application imports it.
- **Contracts consumed:** `@omniboost/contracts` — `ChatRequest`, `ChatTurn`, `ImageAttachment`, `ChatStreamEvent` (and members: `ChatStartEvent`, `ChatTokenEvent`, `ChatCitationsEvent`, `ChatDoneEvent` — including its optional `imageAnalysis`, `ChatErrorEvent`), `Citation`, `FeedbackRequest`, `FeedbackResponse`.
- **External systems called:** The Python automation API (`apps/automation`, `POST /chat` SSE + `PATCH /chat/{traceId}/feedback`) — reached via `server/route-handlers.ts` through `platform/automation-api`, composed by the `app/api/chat/**` route handlers.
- **Database tables owned:** None. Conversation and trace persistence is owned by `apps/automation`.
- **Where it validates untrusted input:** `server/validation.ts` — rejects malformed shape/JSON and enforces a resource-exhaustion body-size ceiling before any network call; the automation API's own business-rule caps (history length, per-turn length) remain authoritative and are forwarded verbatim on rejection.
- **Shared components used:** `app/layout.tsx` mounts `ChatSessionProvider` + `ChatWidget` app-wide (PLAN 4.7.4). Design values come from `@omniboost/design-tokens` via Tailwind utilities. `@/components/layout/page-shell` (`PageShell`) and `@/components/ui/button` (`Button`) are no longer used by this feature as of PLAN 4.7.7 (the `/chat` route and its "Open chat" button were removed); `PageShell` had zero remaining consumers repo-wide and was deleted, `Button` was kept as a generic primitive despite zero current consumers.
- **Tests location / risky paths:** `apps/web/src/features/chat/tests` — SSE stream parsing (multi-chunk, partial buffer boundaries), request validation edge cases, the proxy's auth-header injection + error/streaming passthrough. PLAN 4.7.4 adds `use-widget-visibility` (fake-timer tests proving the exact 3000ms/20000ms timing), `chat-launcher`, `teaser-popup`, and `chat-widget` (open/close/teaser-flow integration) tests.
