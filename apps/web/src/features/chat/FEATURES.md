This file documents every feature in apps/web/src/features. Each block below maps to one folder in that directory. A feature without a block here is undocumented and incomplete.

## chat

- **What it does:** Renders the user-facing chat interface — both the full-page `/chat` route and, as of PLAN 4.7.4, a globally-mounted floating widget (launcher → teaser → panel) — and proxies chat requests to the Python automation API, streaming answers and citations back to the browser; also proxies thumbs up/down feedback.
- **Path / owning app:** `apps/web/src/features/chat` — owned by `apps/web`.
- **Language / framework / runtime:** TypeScript, Next.js 15 (App Router) + React 19, Node.js LTS (server) and the browser (client components).
- **Deployment unit:** Ships inside the `web` Next.js application deployment.
- **Exported symbols (`index.ts`):** `ChatPanel` (the full-page root, rendered by the `/chat` route); `ChatWidget` (the floating launcher/teaser/panel root, PLAN 4.7.4 — mounted once, globally, by `app/layout.tsx`); `ChatSessionProvider` (the shared conversation context, also mounted once by `app/layout.tsx` so `ChatPanel` and `ChatWidget` read one live session, PLAN 4.7.4 architecture decision D0); the view-model types `ChatMessage`, `MessageRole`, `MessageStatus`; and the server route handlers `handlePostChat`, `handlePatchFeedback` (composed by `app/api/chat/**/route.ts`). Internals (`ui/`, `api/`, `model/`, `server/`) are private behind this root.
- **Internal structure:** `ui/` (`chat-session-provider` — conversation state machine behind `ChatSessionProvider`/`useChatSession`, mounted once at the app root as of PLAN 4.7.4; `chat-panel` — renders `panel-body` in its "page" variant, reading the ambient session; `chat-widget` — PLAN 4.7.4's floating-widget root: renders `ChatLauncher` + (conditionally) `TeaserPopup` while closed, or `FloatingFrame` wrapping `panel-body` in its "widget" variant while open, driven by `use-widget-visibility`; `use-widget-visibility` — the launcher/teaser timing state machine (3000ms initial teaser, 20000ms repeat, matching the mockup's own `scheduleTeaser` exactly); `chat-launcher` — the closed-state circular button, pulses via `launcher-pulse` while the teaser is visible; `teaser-popup` — the proactive nudge card, `teaser-in` entrance keyframe; `floating-frame` — the widget's open-state chrome: a fixed-position overlay pinned to the right edge (deliberately *not* the mockup's flex-sibling layout — see PLAN.md 4.7.4's "Panel frame" note); `panel-body` — composition root shared by `ChatPanel` and `ChatWidget`, composing `panel-header` + `message-list` + `composer` (PLAN 4.7.3); `panel-header` — the chrome bar (assistant mark/name, "···"/language/close icon row), owns the two menus' mutually-exclusive open state and wires "Restart conversation" to `useChatSession().restart()` (PLAN 4.7.3); `menu`/`menu-item` — shared dropdown shell for both header menus (PLAN 4.7.3); `language-menu` — the six-locale stub menu, always English-checked, no real switch (PLAN 4.7.3); `message-list`, `message-bubble`, `typing-indicator`, `composer`, `attachment-strip` — client-side image-attachment preview strip (`docs/rag/OBI-WIDGET-DESIGN.md` §6; file-picker + clipboard-paste, no backend send — dropped with an inline notice on send), `icon-button`, `assistant-mark` — feature-only components), `api/` (`chat-client` — browser SSE client over `/api/chat`), `model/` (`messages` — render view-model), `server/` (`route-handlers` — the Next.js proxy to `apps/automation`; `validation` — inbound shape checks, C3).
- **Allowed importers:** `apps/web/src/app` (routes/pages/layout) only, and only via the public root `@/features/chat`. No other feature or application imports it.
- **Contracts consumed:** `@omniboost/contracts` — `ChatRequest`, `ChatTurn`, `ChatStreamEvent` (and members: `ChatStartEvent`, `ChatTokenEvent`, `ChatCitationsEvent`, `ChatDoneEvent`, `ChatErrorEvent`), `Citation`, `FeedbackRequest`, `FeedbackResponse`.
- **External systems called:** The Python automation API (`apps/automation`, `POST /chat` SSE + `PATCH /chat/{traceId}/feedback`) — reached via `server/route-handlers.ts` through `platform/automation-api`, composed by the `app/api/chat/**` route handlers.
- **Database tables owned:** None. Conversation and trace persistence is owned by `apps/automation`.
- **Where it validates untrusted input:** `server/validation.ts` — rejects malformed shape/JSON and enforces a resource-exhaustion body-size ceiling before any network call; the automation API's own business-rule caps (history length, per-turn length) remain authoritative and are forwarded verbatim on rejection.
- **Shared components used:** the chat route wraps the panel in `@/components/layout/page-shell` (`PageShell`); `app/layout.tsx` mounts `ChatSessionProvider` + `ChatWidget` app-wide (PLAN 4.7.4). Design values come from `@omniboost/design-tokens` via Tailwind utilities; `components/ui/button`'s `Button` is no longer used here (PLAN 4.7.2 replaced the composer's send control with a bespoke circular button matching the Obi widget spec's distinct disabled-fill behavior).
- **Tests location / risky paths:** `apps/web/src/features/chat/tests` — SSE stream parsing (multi-chunk, partial buffer boundaries), request validation edge cases, the proxy's auth-header injection + error/streaming passthrough, and (PLAN 4.7.2) the `ChatSessionProvider`/`ChatPanel` characterization tests guarding streaming/citations/refusal/feedback/abort/restart behavior through the widget rebuild. PLAN 4.7.3 adds `menu`/`menu-item`/`language-menu`/`panel-header` tests plus a `chat-panel.test.tsx` case proving restart genuinely clears the thread end to end. PLAN 4.7.4 adds `use-widget-visibility` (fake-timer tests proving the exact 3000ms/20000ms timing), `chat-launcher`, `teaser-popup`, and `chat-widget` (open/close/teaser-flow integration) tests; `chat-panel.test.tsx` was updated to wrap `ChatPanel` in an explicit `ChatSessionProvider` since the provider's mount moved to `app/layout.tsx` (D0). Note: jsdom's `click()` dispatches directly on the target element and does not hit-test through CSS stacking — a real z-index/click-interception regression (see PLAN.md 4.7.3's deviations) can only be caught by live-browser verification, not these unit tests. `attachment-strip.test.tsx` plus `composer.test.tsx`'s "image attachments" block (`docs/rag/OBI-WIDGET-DESIGN.md` §6) cover file-picker upload, clipboard-paste, remove, the 4-attachment cap, and the send-time drop-with-notice behavior — jsdom has no real Blob URL registry, so `test-setup.ts` stubs `URL.createObjectURL`/`revokeObjectURL`.
- **Run / test commands:** Run: `pnpm --filter web dev`. Build: `pnpm --filter web build`. Test: `pnpm --filter web test` (vitest).
