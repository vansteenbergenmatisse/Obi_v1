# retrieval

## Purpose (two lines)
Runs the permission-aware hybrid search: embeds the question, does dense + keyword search over active child chunks under two RLS GUCs, fuses by page id, drops pages the caller's ACL forbids, reranks with Cohere, and writes/updates the `query_trace` row. `apps/automation/app/features/retrieval/__init__.py:1-17`

## Known gaps
- No test in `apps/automation/app/features/retrieval/tests/` exercises `trace_repo.py` at all — `grep -rn "query_trace" apps/automation/app/features/retrieval/tests` returns nothing, so the r1-ctx claim "Every reader transaction in a request logs the same allowed_sources and allowed_scopes to query_trace" has no test evidence in this folder.
- `fetch_page_scopes` (`apps/automation/app/features/retrieval/infrastructure/search_repo.py:214`) and `fetch_parent_context` (`:242`) are only exercised end-to-end in an eval/DB-level path outside this folder (not present as unit or db tests here); no fake-session or db test for either lives under `retrieval/tests`.
- `r2-prov`'s target `Candidate` dataclass (source_type, item_id, keyword_rank, dense_rank, fused, rerank) does not exist anywhere in this folder — `grep -rn "class Candidate" apps/automation/app/features/retrieval` returns nothing. Consistent with the panel's own `build` (proposed) status, so this is a target gap, not a regression.
- `reciprocal_rank_fusion` (`apps/automation/app/features/retrieval/domain/fusion.py:14-28`) fuses **page ids**, not child chunk ids, contradicting `r2-rrf`'s "Target unit: child chunk id" — again the target, not yet built; today's behavior is page-id fusion, confirmed by `retriever.py:161-163`.
- `enable_knowledge_scope_filtering` defaults to `False` in `HybridRetriever.__init__` (`apps/automation/app/features/retrieval/application/retriever.py:102`); whatever value production wiring actually passes is set outside this folder (`app.main`/`rag_agent`), so the r3-scope claim "The app predicate is flag-gated and on" cannot be confirmed from this folder alone.
- The fail-closed default-deny mechanism (`current_setting`/`string_to_array`/`ANY(NULL)`) that `r3-deny` describes has no trace in this folder — `grep -n "current_setting" apps/automation/app/features/retrieval/infrastructure/search_repo.py` and the same grep for `string_to_array` both return nothing; the mechanism lives entirely in the RLS policy DDL (`platform/db/schema.py`), and its named test (`test_rls_default_deny_on_reader_role`) lives in `apps/automation/app/features/confluence_sync/tests/test_retrieval_eval.py`, not in `retrieval/tests`.
