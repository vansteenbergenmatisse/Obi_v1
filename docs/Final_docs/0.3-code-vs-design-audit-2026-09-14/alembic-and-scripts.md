# alembic-and-scripts

## Purpose (two lines)
`apps/automation/alembic/` is the numbered, reversible history of every schema change to the one Supabase Postgres corpus (12 migration files, `apps/automation/alembic/versions/0001_core_schema.py` through `apps/automation/alembic/versions/0012_widen_document_version_idem.py`), run by the table-owner via `alembic upgrade head`.
`apps/automation/scripts/` is the operator's one-off CLI toolbox around that same database and around Confluence — provisioning the reader role, verifying row-security isolation, seeding `source_scope`/`curated_knowledge_entry`, running a manual reconciliation sweep, gating the knowledge-scope backfill, and rotating the chat API key.

## Known gaps

- Migration 0012 (`apps/automation/alembic/versions/0012_widen_document_version_idem.py:44-51`) — the live-verified idempotency-key widening — has no `test_migration_0012_*.py` counterpart in `apps/automation/app/platform/db/tests/`, unlike 0007/0009/0010/0011; its round-trip is asserted only indirectly through `test_worker_sync::test_contextualization_version_bump_rebuilds_at_same_cf_version` per the commit message (`git log -1 2435127`), which lives outside this assignment's two folders.
- `apps/automation/scripts/seed_source_scope.py`, `seed_curated_knowledge.py`, and `rotate_chat_api_key.py` have no test file anywhere in the repository (confirmed by grepping `apps/automation/app` for each script's module name — zero hits beyond `FEATURES.md` prose mentions).
- `apps/automation/scripts/setup_supabase.py:59-92` (`preflight`) and `:128-149` (`provision_reader`) are exercised only by hand against a live/staging Supabase instance per the module docstring (`:8-22`); only `verify_isolation` has automated coverage.
- `apps/automation/scripts/rotate_chat_api_key.py:91` prints the freshly generated `CHAT_API_KEY` to stdout. The docstring at `:64-65` frames this as deliberate ("for the operator's own record — never logged by the running app"), but it is a secret value reaching a terminal/CI transcript, which sits close to CLAUDE.md rule 10 ("No secret in … a log line"). Flagged for review, not called a violation, since the print is operator-facing CLI output, not application logging.
- `apps/automation/alembic/versions/0011_query_trace_subject_hash.py` and `0012_widen_document_version_idem.py` exist and are functional, but neither is named by the `cm-alembic` panel's "Today" enumeration, and the panel's own "target: one migration, 0011" roadmap describes different DDL than what shipped (see Claims table) — the design page's alembic section has not been refreshed since these two migrations landed.
- `apps/automation/scripts/seed_curated_knowledge.py:54-72` never computes an embedding or a `tsvector`; `curated_knowledge_entry` has no `embedding`/`tsv` column in any migration (grep of `apps/automation/alembic/` for `embedding`/`tsv` on this table returns nothing) — the curated-entry relevance search the design describes cannot run until both the column and the seeding step exist.
