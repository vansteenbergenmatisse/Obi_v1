# rag_agent

## Purpose (two lines)
Owns the `/chat` HTTP surface and the fixed answer workflow: verify the caller's key and token, rewrite the question, retrieve/rerank via `retrieval`, decide refusal, expand to parent evidence, generate a cited answer, enforce citations, and stream the result.
Also owns the per-user identity short-circuit, small-talk short-circuit, clarification branch, curated-knowledge composition, PII redaction, and the idempotency/answer caches around that workflow.

## Known gaps
- No per-part coverage check: `decide_refusal` (`domain/refusal.py:53-83`) only ever looks at one top rerank score, never at each question part — `r5-coverage`'s target module (`domain/coverage.py`) does not exist anywhere in this folder.
- No semantic support verification: `enforce_citations` (`domain/citations.py:27-43`) validates only that a marker number is real, never that the cited passage backs the sentence — `r5-ground`'s target module (`domain/support.py`) does not exist anywhere in this folder.
- No dedupe/merge/token-budget logic over parent evidence in this folder: `AnswerService.answer` (`application/answer_service.py:322-330`) passes retrieved hits straight into `build_evidence_block` with no same-parent collapsing, neighbor-merge, or lowest-score-drops-first budget trim — `r5-dedupe`'s target behavior does not exist here.
- `CachingAnswerService` is still wired and tested (`application/answer_cache.py:65-86`, `tests/test_answer_cache.py`) even though `cm-agent`'s own code-location list marks it "(remove)".
- Curated knowledge is still "first five active entries by id" (`infrastructure/curated_knowledge_repo.py:25-29`), not ranked by relevance in the fused pool — matches `r2-curated`'s own disclosed "Today" state, target not built.
- `AnthropicQueryRewriter.rewrite` (`infrastructure/llm_client.py:119-133`) returns a plain string only; it does not emit the `{"query": ..., "parts": [...]}` JSON shape `r1-rewrite`'s target and `r5-coverage`'s per-part check both depend on.
- Image bytes are never PII-redacted, only the accompanying query text is (`infrastructure/llm_client.py:176-193`, disclosed in `domain/pii.py:15-19`).
- `principal` is hard-coded to `None` for every embedded user in v1 (`application/auth_context.py:73, 85`) — no per-person Confluence ACL reaches this feature yet, despite `r1-ctx`/`em-backend`'s `AuthContext` code sample showing a populated `principal`.
- `AuthContext` in this codebase (`application/auth_context.py:40-48`) has no `space_id` field, unlike the `AuthContext` code sample shown on both `r1-ctx` and `em-backend`.
- No `unsupported` refusal reason exists (`domain/refusal.py:42`'s `RefusalReason` literal has only `no_candidates | off_topic | weak_score | no_citations`) — `r5-nocite`'s second refusal path has no code to produce it yet.
