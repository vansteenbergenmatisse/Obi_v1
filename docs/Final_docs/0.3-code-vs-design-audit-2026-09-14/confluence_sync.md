# confluence_sync

## Purpose (two lines)
Hears Confluence webhook events, records them idempotently, and turns them into idempotent background jobs; a worker claims and runs those jobs (sync/delete/reconcile-space); daily/periodic sweeps (`reconciliation.py`) catch drift the webhook missed and resolve `source_scope` roots plus page labels into knowledge-scope tags.

## Known gaps
- `domain/change_detection.py` does not exist in `confluence_sync` — `classify()`/`ChangeClass` actually live at `apps/automation/app/features/ingestion/domain/change_detection.py:104`. Panels `i2-hash` and `i2-classify` (and `cm-sync`'s own code-locations list) cite the path as `confluence_sync/domain/change_detection.py`, which is wrong; verified by `grep -rln "change_detection" apps/automation/app/features/confluence_sync` returning no results.
- No "classified" label state exists anywhere in `confluence_sync` (`grep` for `classified`/`unlabeled`/`scope_state`/`UNLABELED` in this folder returns zero hits). `resolve_knowledge_scope_tags` (`domain/knowledge_scope.py:24-31`) only returns `(tags, conflict, matched_labels)` — no `State.CLASSIFIED`/`State.UNLABELED`/`State.OK` enum as shown in `i2-labels`'s "Code" block. Consistent with those panels' own status words (`build`), so this is a disclosed gap, not a silent one.
- The idempotency key for `sync_page` jobs includes `event_type` (`application/event_service.py:94`: `f"{JOB_SYNC_PAGE}:{page_id}:{event_type}:{ver}:{schema}"`), so a `label_deleted` immediately followed by a `label_added` produces two distinct pending jobs today, not one coalesced job. The target partial-unique index `ux_job_pending_sync_page` on `(page_id) WHERE status='pending'` named in `i1-enqueue`'s "Code" block was not found in this folder (migrations live outside `confluence_sync`) — not audited further per assignment scope.
- Two tests named by `i1-enqueue` ("Two label changes at one page version both apply", "A label change during a running rebuild produces a second run after the first") were not found under this test tree — `grep -n "^def test_"` on `tests/test_worker_sync.py`/`tests/test_event_dedup.py` lists no matching test names.
- `tg-change`'s test claim ("No stale double tag after mews to toast") was not found as a named test in this folder; `grep -rln "stale"` over `tests/` returns only version-guard-related hits in `test_worker_sync.py` and `test_versioning_rollback.py`, unrelated to label swap.
- `ks-sweep`'s target (daily CQL label search across all spaces) is not implemented; `reconciliation.py`'s sweep still walks `source_scope` roots end to end (`_sweep_space`, `application/reconciliation.py:145-221`), matching `cm-sync`/`i1-sweep`'s own "Today" line — not a contradiction, but the biggest planned-vs-built gap in this folder.
- `ks-orphan`'s target (a page losing its only recognized tag deactivates on the next sweep) is not implemented either: `sync_service.py:115` computes `final_tags` but an empty result never triggers `deactivate_page` — same underlying gap as `tg-remove`.
- `tg-purge` and `tg-state` (chunk-row deletion on purge; a stored `scope_state` enum) are both schema/target work with zero trace in this folder — `grep -n "delete(Chunk)"` and the earlier `scope_state` grep both return nothing.
- Twelve files under `confluence_sync/tests/` (`test_chat_endpoint.py`, `test_answer_workflow.py`, `test_retrieval_eval.py`, `test_fallback_eval.py`, `test_router_auth_context.py`, `test_customer_isolation_backstop.py`, `test_reader_rls_reconcile.py`, `test_reader_vector_access.py`, `test_force_rls_managed_postgres.py`, `test_curated_knowledge_repo.py`, `test_verify_isolation_script.py`, `test_retrieval_knowledge_scope.py`) import and test `app.features.rag_agent`, `app.features.retrieval`, and `app.platform` end to end (e.g. `test_chat_endpoint.py:15-19` imports `Answer`, `AnswerProvider`, `AnswerService`, `AuthContext`, `CachingAnswerService` from `app.features.rag_agent`). This is a placement drift against CLAUDE.md's "Tests... next to the feature they cover" rule; sibling features (`rag_agent/tests/`, `retrieval/tests/`, `ingestion/tests/`) each hold only their own tests.
- `i2-hash`'s claim that `platform/db/models.py` stores the five hashes on `page_source` and `document_version` is not audited here (owned by platform) — only the confluence_sync-side production of those hash values via `decision.*` in `sync_service.py:159-165` is confirmed.
