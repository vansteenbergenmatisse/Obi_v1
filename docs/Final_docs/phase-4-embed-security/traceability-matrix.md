# Obi Embed Security Core — Requirement Traceability Matrix

Synthesis of five independent read-only audits (Browser/iframe, Authorization/retrieval isolation, Confluence/identity permissions, Lifecycle/concurrency/stale-state, Config/migration/CI). One row per requirement, grouped by domain. Status vocabulary: **working** (implemented + tested), **partial** (implemented but a defense-in-depth or test gap), **missing** (a required behavior or its only-enforcement is absent).

> Note on the "15 mandated test-contract items": the mandate's verbatim 15-item list was not supplied in this synthesis run's inputs. Section 1 reconstructs the 15 contracts from the union of mandated security behaviors across the five audits and maps each to covered/partial/missing with evidence. Every mapping is anchored to a concrete requirement row and file evidence below.

## Section 3 — Prioritized gap list

Ranked by security severity, then blast radius. Test-only gaps are separated from genuine missing behaviors.

### Genuine missing/incomplete security behaviors

1. **[HIGH] LC-1 + LC-4 — obi:clear is not a real logout.** Clearing hides the panel but leaves the conversation, conversationId, and in-flight stream alive on the always-mounted ChatSessionProvider; a re-open shows the old thread and a late answer generated under the pre-logout token lands in it. Fix: route obi:clear through `useChatSession().restart()`.
2. **[HIGH] CFG-02 — test/placeholder platforms can be active in production.** No guard rejects a test-* platform, `.local`/placeholder issuer, or non-https jwks on an active entry outside local. Fix: extend the `if not allow_empty:` prod branch to reject them.
3. **[HIGH] CFG-04 — localhost domains can enter the production frame CSP.** activeDomains emits any active entry's domains verbatim; a non-empty localhost list passes and becomes frame-ancestors in prod. Fix: same prod-hardening guard as CFG-02 (reject localhost/127.0.0.1).
4. **[MEDIUM/HIGH] LC-5 — clear-vs-token-fetch race.** A token fetch in flight when clear() runs resolves afterward and re-posts obi:token, resurrecting the cleared token. Fix: module-scoped epoch counter guarding postToFrame after lifecycle transitions.
5. **[MEDIUM] CIP-4 — token_subject not namespaced by issuer.** Identical sub from two trusted issuers collides across rate-limit bucket, idempotency key, answer_cache key, and audit fingerprint. No content leak in v1 but a latent cross-tenant leak once per-principal ACL or issuer-specific mapping lands; today causes cross-issuer rate-limit interference + ambiguous audit. Fix: `token_subject = f"{claims.issuer}\0{claims.subject}"`.
6. **[MEDIUM] LC-2 / LC-3 / LC-6 — silent scope change on token renewal.** A renewal-borne company/integration change (no Obi.init) is not detected; the open conversation is not reset and old-scope turns are resent as history; onUnauthorized has no subscriber so a 401 never clears stale UI. Fix: decode integration/company on obi:token and restart() on change; subscribe onUnauthorized.
7. **[MEDIUM] CFG-05 — backend/frontend disagree on the prod env signal.** Different var names (ENV vs APP_ENV) and different accepted sets ('development' = prod for backend, non-prod for frontend). Fix: align the sets and document one canonical signal.
8. **[MEDIUM] MIG-02 — no deploy-blocking readiness gate for 0010.** 0010 is operator-applied with no automated check that the reader path isn't exposed before the scope policies exist. Fix: readiness assertion querying pg_policies for chunk_scope_read + curated_knowledge_entry_scope_read.
9. **[LOW→MEDIUM] CIP-5 — page-principal ACL is app-layer only.** No RLS backstop for page_restriction (0009 gives it USING(true)); safe in v1 because principal is always None, but must gain a DB backstop before per-principal ACL is enabled. Fix (v1): record as a known defense-in-depth gap (ADR/ledger).
10. **[LOW] BIT-7 — obi:token field not runtime-validated.** Type set is filtered but token value shape is TS-only. Fix: guard non-empty-string before storing.
11. **[LOW] BIT-10 — no server-only trip-wire on automation-api/client.ts.** Host key cannot leak today (non-NEXT_PUBLIC + no client importer) but relies on convention. Fix: add `import "server-only";`.
